# Hotfix: import the Howell NW hardware sets on production

**Stopgap, not a release.** This writes two files into the running `app` container's writable layer (the
`configurator:import-fab-utils-hwsets` command, and the Howell NW export it reads). Both are wiped on the next
image pull. The command is already on `develop`, so once a release containing it is deployed you can skip the
first block and just run the import (see "After the next release" at the bottom).

Run everything from the directory on the production box where the right compose file is the default (no `-f`).

**What it does:** adds 15 hardware sets (H01-H15, H12 and HW14 are pairs) to the job numbered **4250403 (Howell NW)**.
It only creates sets. Existing sets with the same name on that job are skipped, nothing is applied to openings, and
the dry run writes nothing. If the production hardware library is missing any item/variable the sets use (19 items,
4 variables, matched by exact name) or the job doesn't exist, it prints what is missing and writes nothing.

Source of the export: fab_utils job 29 "Howell NW" (`hwlib_sets` / `hwlib_set_items` / `hwlib_set_item_values`),
exported 2026-10-07 with items and variables referenced by name/code.

## 2. Dry run, then import

```bash
docker compose exec app php artisan list | grep import-fab-utils-hwsets    # should list the command
docker compose exec app php artisan configurator:import-fab-utils-hwsets /tmp/howell_nw_sets.json --job=4250403 --dry-run
docker compose exec app php artisan configurator:import-fab-utils-hwsets /tmp/howell_nw_sets.json --job=4250403
```

Expected dry-run output: 15 `create` lines and `[dry run] Job 4250403 Howell NW: 15 created, 0 replaced, 0 skipped.`
Re-running later is safe: existing sets show as `skip`. Add `--replace` only to overwrite a set's items.

If the command isn't listed, clear the cached bootstrap files and check again:
`docker compose exec app php artisan optimize:clear`.

## 3. Clean up

```bash
docker compose exec -T -u root app rm -f /tmp/howell_nw_sets.json
```

The command file can stay (it's identical to what the next release ships), or be removed with
`docker compose exec -T -u root app rm -f /var/www/html/app/Console/Commands/ImportFabUtilsHwSets.php`.

## After the next release

The command ships in the image. You only need the data file, e.g. write it with the second paste block above and run
step 2 unchanged.
